# 检查与验收

阅读限制见 [README.md](README.md)。

## 离线检查

构建脚本会自动执行前三项；后两项看图。

| 检查 | 方法 | 能证明 | 不能证明 |
|---|---|---|---|
| 加载校验 | `python -m dayart.validate <包.zip>`：按 `DayMapRegistry.Validate` 的规则检查容量、切片越界、key 重复、排序层、坐标、坡度、出生点、相机、WAV | 配置能通过 Mod 校验 | 好看、可玩 |
| 连通性 | `WalkGrid.check`：可走网格按人物半径 0.3 格腐蚀后标连通区，检查出生点是否连通、有无孤立的可走区 | 网格近似下可达 | 游戏物理下一定可达 |
| 坡度格 | `WalkGrid.check_slopes`：坡度格必须与可走区域重叠 | 坡度没有放错地方 | 坡度方向与美术一致 |
| 往返渲染 | 解包后用 `render_ref.py` 重新渲染，与构建预览对比 | 切片 rect、pivot、图集换算正确 | 运行时材质与排序 |
| 调试叠加图 | `debug.png`：碰撞（红）、坡度（蓝正、橙负，白线为向右走的方向）、出生点（绿）、相机中心范围（青） | 人工核对碰撞与美术贴合 | — |
| 标注图 | `annotate.py`：在解包渲染的 1:1 图上标网格坐标、碰撞、坡度值、出生点与朝向、相机范围与默认画面、物件名、分区，附图例；数据全部读自资源包 | 人工核对与交流（策划、美术、NPC 落位） | — |

示例：三途川构建时，加载校验发现光晕层与地面层的切片 key 都以 `g` 开头而重复，这会使整张地图被 Mod 拒绝；往返渲染确认了图集页裁剪后左下原点 `rect` 的换算。

## 预览审阅

- 总览（1/4）看分区、路径、焦点和明暗分布；1:1 裁切看笔触、描边、比例。
- 固定一组裁切区域（`maps/<name>/crops.py`），每轮构建看同一组，便于前后比较。
- 与原版同类区域的 1:1 裁切并排比较：水岸、卵石、树冠、崖面、摊位。
- 常见问题与改法：

| 现象 | 原因 | 改法 |
|---|---|---|
| 色块碎、像迷彩 | 量化后没有众数滤波，或噪声频率太高 | 众数滤波加大核；降低噪声频率 |
| 雾像地面污渍 | 用了块状噪声的雾 | 改成横向雾缕 + 纵深雾霭；可走区上空压低透明度 |
| 物件看不清 | 主色像素太少、与地面同色 | 主色占大部分像素，提亮或加深描边 |
| 随机物件压住地标或路口 | 散布没有避让 | 散布前扣掉路径、出入口、地标周边 |
| 高处看不出高差 | 只有朝北或朝东的边 | 加侧面立面或临边岩石 |
| 大片区域单调 | 单一材质均匀铺满 | 密度场分出疏密，加小路、水洼、苔斑等打断 |

## 游戏内核对

1. 资源包放入游戏的 ResourceEx 目录并重启；BepInEx 日志出现 `Registered day map <id>`，没有 `dayMaps[...]` 校验错误。
2. `/resourceex map goto <id> [出生点]` 逐个进入出生点；`/resourceex map back` 返回。
3. 清单：
   - 相机：走到四边和四角，不露出地图外。
   - 碰撞：沿水边、崖边、林边走一圈，无穿模、无卡住；窄口能顺畅通过。
   - 坡度：在阶梯和拱桥上只按左右键，人物沿美术走向移动。
   - 排序：从物件前后各走一次（积石、灯笼、摊位、树、桥栏杆），遮挡关系正确。
   - 前景层：树冠、门楣、灯笼串、雾不过多遮挡主要路径上的人物。
   - 加载：进图耗时与原版同类地图相近。
4. 结论按“运行时实测 / 源码推断 / 待验证”记录。
