# 生图重绘流程

阅读限制见 [README.md](README.md)。

程序化绘制（[art-pipeline.md](art-pipeline.md)）能精确控制布局、碰撞和坡度，但笔触和物件造型很难接近原版手绘。实际做法是分工：代码负责布局和玩法数据，生图模型负责画面，最后再用代码把画面拆层、量位置、生成碰撞并打包。

本流程需要一个支持“参考图 + 文字”编辑的生图模型。三途川示例用的是 gpt-image-2，单张最大 3456×2304，一张 2–4 分钟。

## 总体步骤

| 步骤 | 输入 | 输出 | 由谁做 |
|---|---|---|---|
| 1. 布局底图 | `layout.py` 与程序化构建 | 不含雾和光、带树冠的整图（缩到一半） | 代码 |
| 2. 整图重画 | 底图 + 2–3 张原版截图 | 带物件的成品总图 | 模型 |
| 3. 地面层 | 成品总图 | 去掉所有立着的物件、只剩地面的图 | 模型 |
| 4. 分块细化 | 地面层切成 20 个重叠窗口 | 每块重新画清楚，再拼回整图 | 模型 + 代码 |
| 5. 物件图 | 原版截图 + 地面层截取 | 纯色底的物件表，切成独立精灵 | 模型 + 代码 |
| 6. 组装 | 地面层、精灵、摆放表 | 分层、碰撞、坡度、文字、光效、资源包 | 代码 |

## 1. 布局底图

- 用程序化版本出图，只保留地面、物件和树冠，去掉雾和光：这两层会被模型当成实物画进去。
- 缩到一半再交给模型。模型的输出尺寸上限就是地图的 1:1 尺寸，喂原尺寸也不会更清楚。

## 2. 整图重画

- 一次画整张图。分块重画的结果每块风格不同，接缝处对不上。
- 参考图挑与目标地貌接近的原版截图（1:1 裁切），2–3 张，至少一张有水、一张有草地和小路。
- 提示词写三件事：风格（引用参考图）、“保持图 1 的构图，所有区域和物件位置大小不变”、逐区域的景物清单。再写一句“不要文字、不要人物、不要边框”。
- 同时生成 2–3 张挑最好的。会出现的问题：多画或少画小物件，把河中的物件画到岸上，岸线偏移 0.5–3 格。挑图时先看岸线和主要建筑。

## 3. 地面层

- 在成品总图上做编辑：逐个点名要去掉的物件，再列出必须保留的地面结构（水、岸、路、栈桥、桥、石墙、台阶）。
- 地面层和成品总图的岸线只差 1–3 像素，可以直接用。两张图相减就能看出每个物件原本的位置。
- 地面层上多留下的残影，用旁边干净区域的像素覆盖（`place.PLATE_PATCHES`）。

## 4. 分块细化

整图生成的细节偏糊。把地面层切成 4×5 个 960×640 的窗口（相邻窗口重叠约 1/3），逐块交给模型重新画清楚（`refine.py split`），再拼回去（`refine.py stitch`）：

- **配准**：只在 ±8 像素内找平移，而且要比不平移的结果明显更吻合才采用；水面、林冠这类纹理弱的区域很容易配错。
- **校色**：只校正低频颜色。每 32 像素一块取差值的中位数，平滑后加回去，并限制幅度。用高斯模糊做校色，会在两张图内容不同的地方抹出色斑。
- **拼接**：在重叠区里沿差异最小的路径切开，接缝处羽化 2 像素。
- **远景**：最远的一条保留原图并渐变过渡。远处本来就该更虚，细化反而会把远岸画成近景。
- 提示词里可以顺带改一处，例如“把满地卵石改成细砾石，大卵石聚成小簇”，其余内容要求不变。

## 5. 物件图

- 每张表 8–13 个物件，按类别分组（石、木、摊位、树、小物件），在纯色底上分开排列。参考图里放一张地面层截图，让物件配色跟上地图。
- 底色避开物件颜色：大多数用纯绿 `#00FF00`；树木和绿色物件用纯品红 `#FF00FF`，同时要求物件不用品红或粉色。
- 切图（`sprites.py`）：按与底色的距离抠图，去掉边缘和枝叶缝里带底色色相的像素，再压低残留的溢色。紫色花树这类本身接近品红的物件，加进 `keep_hue` 名单，跳过去溢色。
- 模型给的尺寸不可靠，统一按目标高度（或宽度）缩放到游戏尺寸，记在 `sprites.json`。参照：人物约 48 像素高，石灯笼约 78，摊位宽约 180。
- 招牌、幡、碑上的字一律留空，组装时用像素字体写上。模型写的汉字基本都是错的。

## 6. 组装

见 `maps/sanzu/assemble.py`。

- **测量地形**：在地面层上叠世界坐标网格出放大图（`gridcrop`），量出栈桥、桥、石墙、台阶、码头的位置，写进 `place.py`。可走区域、坡度、物件位置都按画面来，不按旧布局。
- **水面与林冠**：用颜色识别。水面：色相 165–215、饱和度和明度不太低，去掉小块。林冠：深绿；只保留面积大或接到地图边缘的连通块，否则场地中间的深色草斑会被当成树冠。
- **可走区域**：去掉水和离岸 0.3 格的一圈，以及林冠上缘往里 0.8 格之后的部分（人物可以走进树冠下缘被遮住）。再挖掉石墙和台地边缘，加回栈桥、码头、桥面和台阶。最后只保留与出生点连通的部分。
- **拱桥**：可走带沿拱形中线走；坡度按拱形每列取值（+0.75 到 −0.75）。南侧栏杆和桥身从地面层抠出来，做成按 Y 排序的物件，人物走上桥面时会被挡住下半身。
- **物件**：精灵向地面的阴天光线调色（饱和度 ×0.86、明度 ×0.92、叠一层冷灰），脚下烘一圈柔边接触投影。碰撞框贴在脚点上方。
- **光与雾**：灯火和人魂加径向渐变光晕，河面加一层越远越浓的横向雾。生图的画面本来就有柔和渐变，这里不再坚持 [art-pipeline.md](art-pipeline.md) 里的硬边分级。
- **切片**：地面层用 4×4 格大切片。生图的地面几乎没有重复，1×1 切片去重省不了空间，切片数还会超限。资源包约 20 MB。

## 检查

除 [debugging.md](debugging.md) 的离线检查外，生图版还要看：

- 拼接处有没有错位、色斑（看 1:1 裁切，重点看水面和林冠）。
- 精灵边缘有没有绿色、品红色残留（3 倍放大看）。
- 碰撞叠加图里，水边、石墙、林冠边缘的红框是否和画面对齐。
- 文字是否清楚，是否和摊位、幡的内容对应。

## 注意

- 参考图会上传到生图服务。是否允许上传原版截图，由项目负责人决定。
- 生成的图片和提示词都是这张图的“源文件”：提示词放在 `maps/<name>/prompts/`；图片体积大，不进仓库，本机位置记在 `paths.local.md`。
- 同一提示词每次结果都不同。改动要在已选定的图上做编辑，不要从头重新生成。
