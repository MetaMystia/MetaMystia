# 服务端聊天过滤

独立服务器启动时读取程序所在目录的 `chat-filter.json`。将同目录随构建输出的 `chat-filter.example.json` 复制为该文件，修改词表后执行 `reload` 或重启服务器。

```json
{
  "enabled": true,
  "ignoreCase": true,
  "words": ["示例敏感词", "示例禁止内容"]
}
```

- `enabled`：是否启用敏感词检查，默认关闭。
- `ignoreCase`：是否忽略大小写，默认开启。
- `words`：正文包含任意词条即拒绝；空字符串、纯空白词条忽略。词条不自动去除首尾空格。
- 配置不存在时关闭过滤；配置无法读取、JSON 无效或 `words` 不是字符串数组时启动失败；`reload` 遇到这些错误保留原配置，不静默跳过。
- 实际配置已加入 Git 忽略列表；示例文件不自动启用。支持 `reload` 热更新；暂不支持正则、拼音、全半角或零宽字符转换。

服务器解析共享 `ChatPayload`，检查正文非空、长度不超过 1024 个 UTF-16 单元，序列化正文不超过 4096 字节。敏感词或无效正文只向发送者返回拒绝提示，不转发、不因该拒绝断线。传输层损坏、非法路由和队列超限仍遵循原网络处理。

通过检查的聊天向整个世界广播，包括发送者。联网客户端仅收到确认后的正文才显示聊天和气泡；离线控制台保留本地显示。过滤不涉及玩家名。

聊天正文协议已变更，服务端与客户端需一起更新。目前协议版本保持为 0，兼容性以模组版本号校验为准。局域网共用检查逻辑，默认没有敏感词表；本配置文件仅由独立服务端入口读取。
