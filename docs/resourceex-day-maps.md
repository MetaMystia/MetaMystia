# ResourceEx 白天地图首版

资源包在 `ResourceEx.json` 的 `dayMaps` 数组声明地图，图片和音频放在同一 ZIP。Mod 从配置创建独立 `DaySceneMap`，通过内存 Addressables Provider 交给游戏原有切图流程实例化。

## 使用

安装 ZIP 后重启游戏，在单机白天自由活动时使用：

```text
/resourceex map list
/resourceex map goto 1073742000
/resourceex map goto 1073742000 East
/resourceex map back
```

`goto` 不扣行动点。首次进入时记录原地图的一个有效出生点，`back` 返回该点；不是恢复原来的精确坐标。返回记录仅在当前白天场景有效。地图不解锁到世界地图面板，不创建出口，也不挂靠原有区域。联机连接期间禁止这些指令。

地图 ID 参加现有资源包 ID 范围与签名校验。运行时标签为 `_ResourceEx_Map_{id}`，出生点为 `_ResourceEx_Map_{id}_{name}`。重复地图 ID 全部停用，避免由包扫描顺序决定地图归属。首版没有修改网络 `MapLabel` 枚举或通信协议。

## 配置

| 字段 | 用途 |
| --- | --- |
| `id`、`formatVersion` | 整数地图 ID；格式版本目前为 `1` |
| `name`、`description` | 地图名称与描述 |
| `tiles` | 可复用切片：`key`、`image`、`rect`、`pivot`、`pixelsPerUnit` |
| `layers` | 固定排序的瓦片层：`name`、`sortingLayer`、`sortingOrder`、`cells` |
| `height` | 可选坡度层，`cells` 中保存 `x/y` 和 `slope` |
| `objects` | 单独摆放的装饰：`tile`、`x/y`、`scale`、`sortByY`、排序设置 |
| `collisions` | 独立矩形碰撞：中心 `x/y`、`width/height`、可选 `name` |
| `spawnMarkers` | 出生点：`name`、`x/y`、`rotation`，默认朝 `Down` |
| `defaultSpawnMarker` | 不指定出生点时使用的名称 |
| `camera` | `shouldFollow`、`bounds`、固定相机 `position` |
| `mapBGM` | 必须提供可解码的 `intro`、`loop` 音频资源 |

所有资源路径均支持包内相对路径和 `rex://` URI。首版音频使用加载器支持的 WAV。

切片 `rect` 是 `[左, 下, 宽, 高]`，以图片左下角为原点，单位为像素。`pivot` 为切片内归一化锚点，默认 `[0,0]`；`pixelsPerUnit` 默认 `48`。48×48 的默认切片对应一格。大图可以用一个较大切片放入图层，不强制切成小格。

`cells` 保存 `{ "x": 0, "y": 0, "tile": "grass" }`，只记录有内容的格子。同一层同一格只能有一项；坐标右正、上正。网格固定一格一个世界单位，切片以其锚点对齐格子原点。

地面通常使用 `Background`，默认顺序 `-2000`；固定前景可使用 `Overlay`。需要与角色前后交错的树等放进 `objects`：默认 `Character` 层并启用 `sortByY`，接入原游戏 `LayerSortingController`。物件锚点应放在脚部，配置的排序顺序会被按 Y 排序覆盖。

碰撞与美术独立，首版只支持轴对齐矩形。水面是否能走由碰撞决定，图片透明度不自动生成碰撞。

`camera.bounds` 是 `[最小x, 最小y, 最大x, 最大y]`，表示原游戏相机中心可移动范围，不能直接填图片外框。它需要考虑视口、原相机偏移及像素对齐。测试包提供适配当前 16:9 视口的范围；其他比例需要单独检查。`shouldFollow: false` 时使用 `position: [x,y,z]`。

## 坡面高度

`height` 对应游戏 `DaySceneMap.height`，与显示图层、碰撞分开。省略、设为 `null` 或提供空 `cells` 均为平地，旧包无需修改。示例：

```json
"height": {
  "cells": [
    { "x": -14, "y": -6, "slope": 0.5 },
    { "x": -13, "y": -6, "slope": 0.5 },
    { "x": 8, "y": -4, "slope": -0.5 }
  ]
}
```

`slope` 范围为 `[-1,1]`：正值表示向右上坡，负值表示向右下坡，`0` 或空格表示不修正移动。比如 `0.5` 表示仅向右移动时，横向每前进 1 单位，纵向约增加 0.5；向左则反向下降。每格内坡度恒定，最多 100000 格，不允许重复坐标、非有限数或越界坡度。

Mod 创建不可见的 `HEIGHT_MAP` Tilemap 并赋给原生 `height`。按原游戏采样方式，把绝对坡度写入纹理红色通道，绿色通道区分正负；纹理保持可读。使用 RGBA32，大小量化为 `round(abs(slope)×255)/255`，例如 `0.5` 实际约为 `0.501961`。同坡度共享瓦片，每张地图共用一张 256×2 的数据图，不需要作者绘制或导入颜色编码图。

原游戏 `DayScenePlayerInputGenerator.UpdateCharacter` 在切图时重新绑定高度图，`HeightBlendedInputProcessorComponent` 根据脚下格子修正输入：`输出y = 输入y + 坡度×输入x`。剧情中和原输入 `y > 0.70700002` 时跳过修正，本实现保留这一行为，不另加移动补丁。

这是斜向地面上的移动规则，不保存角色的绝对海拔，不创建三维地形，也不支持同一位置的桥上、桥下双层通行。坡面外观由美术绘制，坡边由碰撞限定；高度层不会自动移动图片、生成碰撞或改变前后遮挡规则。

未来编辑器可提供“平地、向右上坡、向右下坡”和坡度大小画笔，用箭头覆盖显示，导出上述格子。正负方向以世界坐标为准，界面向下的像素坐标需在导出时转换。

## 加载和校验

包解析后合并配置；白天数据库初始化时先校验，再创建非激活、常驻的地图模板和瓦片对象，注册地图数据库与语言。游戏切图只实例化模板，离开时销毁实例；模板保留到游戏退出，不支持热重载。

校验覆盖缺失图片或音频、越界切片、无效排序层、重复瓦片键/格子/出生点、不存在的瓦片引用、非法坐标尺寸，以及出生点中心落在碰撞内。它不能证明角色整个身体不会贴墙，也不能证明地图可达性，需要实际移动检查。

单地图限制：4096 个切片、32 层、总计 100000 格、4096 个装饰、4096 个碰撞箱、256 个出生点。校验失败的地图不进入数据库，其余资源仍可加载，错误见 BepInEx 日志。

## 测试包与编辑器接口

在仓库根目录运行：

```text
python src/MetaMystia.AITest/create-day-map-package.py .tmp/day-map/IsolatedMapTest.zip
```

生成器仅负责制作测试用的 JSON、PNG、WAV。Mod 不依赖生成器；未来编辑器导出同样的 ZIP 即可。0.2.0 测试地图包含河流、木桥、前景栏杆、按 Y 排序的树、边界碰撞、两块坡面和四个出生点。用 `goto 1073742000 SlopeUp` / `SlopeDown` 进入正、负坡度区域。

编辑器可把 `tiles` 显示为画笔面板、`layers` 显示为图层列表，另外提供装饰摆放、碰撞矩形工具和出生点工具。整图导入和瓦片绘制都落到这些数据，不需要两套运行时加载器。

已支持平地及原生坡面输入；未添加采集点、NPC 配置、出口或传送面板。存档移除地图包后的恢复、联机和其他屏幕比例尚需后续验证。

## 后续基础能力

当前已具备一张可进入、可移动、可离开的独立地图所需的主要运行组件。下一步建议优先补齐：

- 多边形碰撞：贴合斜坡侧边、弯曲河岸和不规则建筑；矩形拼接仍会形成台阶边缘。
- 相机适配：根据可见地图范围、屏幕比例和原游戏偏移计算相机边界，减少作者手算。
- 地图检查：出生点与玩家完整碰撞体是否重叠、坡面是否延伸到障碍内、区域是否可达。
- 生命周期验证：日终、再次读档、资源包升级或移除后的行为，尤其是返回入口失效时的恢复。

原 `DaySceneMap` 另有隐藏时钟和角色头顶图标的开关，可在需要特殊场景时开放。环境音、动画瓦片、水面和天气属于表现扩展，不影响当前基础地图成立。编辑器、传送面板和采集物另行实现。

环境：游戏 RELEASE 4.4.0e、Unity 2021.3.28f1、MetaMystia 0.27.0 本次构建，原示例包与独立 `IsolatedMapTest` 同时加载；单机，1280×720，8 月 8 日白天，初始 16 行动点。未主动存档。

| 检查 | 运行时结果 |
| --- | --- |
| ZIP 加载 | 1 张 PNG、1 个 WAV；地图 ID `1073742000` 登记成功 |
| 原生实例 | 720 格地面、12 格花丛、6 格前景；6 个碰撞箱、2 个出生点；BGM 有效 |
